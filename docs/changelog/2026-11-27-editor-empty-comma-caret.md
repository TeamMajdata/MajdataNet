# 时间轴落在「空逗号」上：光标和黄色三角始终对齐

日期：2026-11-27
分支：`main`

## 背景

`buildTimeline` 之前只给**产生 timing 的格子**记时间：`parseChart` 对只有命令（`(180)`、`{16}`）
或完全是空格的格子（`,,`）不会产生 `noteTimings`，所以这些格子在时间轴上不存在。

后果：

- `Ctrl+←/→`、`Ctrl+点击` 按文本逗号移动光标，到了空逗号上 `timeAtPosition` 只能退回上一个
  音符格子的时间 —— 光标在空逗号、三角停在上一个音符，两者对不上；
- 拖动时间轴时 `positionAt` 只可能落回音符格子，光标跳不过空逗号；
- 光标时间落在时间轴窗口外时，黄色三角根本不画，用户移动光标看不到任何变化。

## 前端改动

| 位置 | 改动 |
| --- | --- |
| `src/utils/simaiTimeline.ts` | 改为按**逗号格子**建表：`parseChart` 的 `commaTimings` 每个逗号一条（末尾格子也有一条），直接配时间；格子位置取第一个非空白字符，空格子取格子起点。`positionAt` / `timeAtPosition` / `lineAt` 的语义统一到格子粒度 |
| `src/majview/visualizer.js` | 黄色三角越界时**钉在窗口对应的一侧**并在最边缘加一条短竖线（提示光标在视野外的哪一边），不再整个不画。**视口仍然以播放头为中心（红线固定在中间），拖动的行为没有改** |
| `src/components/editor/SimaiCodeEditor.tsx`、`src/pages/EditorPage.tsx` | 详细日志里补上「Monaco 选区变化」「光标移动」「光标时间」三条，方便以后再排查光标/三角不同步 |

## 验证

- `test/utils/simaiTimeline.test.ts` 按新语义重写（17 个用例）：每个逗号格子一条时间、空格子
  有自己的时间和列、`positionAt` ↔ `timeAtPosition` 对**每个格子**（含空格子）往返一致、
  注释行不占位、坏谱面返回 null。
- 浏览器（真实谱面，`?debug=1`）：
  - `Ctrl+→` 连续移动时时钟按格子推进，黄色三角随之滑动（实测三角 x：508 → 520 → 543 → 554 → 566）；
  - 拖动时间轴：红色播放头仍在画布正中（实测 `width/2 = 675`，扫描到 676），
    光标落到拖到的那一格；拖到第一个格子之前时光标不动、三角钉在右侧边缘并带短竖线。
- `pnpm lint`、`tsc -b`、`pnpm exec vitest run test/utils/simaiTimeline.test.ts` 通过。

## 注意

- 只改了「格子 → 时间/位置」的映射和三角的绘制，**没有改时间轴视口跟随逻辑，也没有改拖动的
  播放头居中行为**。
- 空格子的光标位置是「前一个逗号后面那一列」（格子起点）；有内容时指向第一个非空白字符。
- 谱面格子和 `commaTimings` 数量对不上（异常谱面）时按较短的算，避免整体错位。
